# Exclusive claim (`tb next` / `run start --exclusive`) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let agents claim an existing ready card without colliding: `run start --exclusive` conflicts when the card already has a running/waiting run, and `tb next` atomically starts a run on the first claimable ready card.

**Architecture:** Keep flag-less `run start` parallel. Add `AppError::Conflict` (`code: "conflict"`). `run_start_inner` takes `exclusive`; when true, reject if any run on that task is `running` or `waiting`. `App::next` holds one store transaction: query `--ready`, skip cards that already have an open run (waiting-on-todo is `--ready` today), exclusive-start the first remaining card, optionally `task move in-progress` when `--move` is set. MCP exposes `run_start` (with `exclusive`) and `next`.

**Tech Stack:** Existing Rust crates, clap, serde JSON, assert_cmd, MCP stdio tests.

## Global Constraints

- Four columns stay `todo | in-progress | in-review | done`
- Finishing a run does not move the card
- Flag-less `run start` stays parallel-capable
- `tb next` does not auto-move the column unless `--move`
- This is a claim on an existing card, not `tb work start`
- No remote MCP; HTTP stays human-facing
- CLI `--json` stays snake_case
- Failure for an occupied exclusive start is `conflict` (not `revision_conflict`)

**Interfaces:**
- Consumes: `run_start_inner`, `task_query` ready filter, `task_move_inner`
- Produces:
  - `AppError::Conflict { entity: String, id: String }` → `code() == "conflict"`, Display `{entity} {id} already has an open run`
  - `pub struct NextClaim { project: Option<String>, agent: String, session_id: Option<String>, move_to_in_progress: bool }`
  - `App::run_start_exclusive(actor, cmd: RunStart) -> Result<Run, AppError>`
  - `App::next(actor, cmd: NextClaim) -> Result<Run, AppError>`
  - Exclusive: any `running`/`waiting` run on the task → `Conflict { entity: "task", id: TASK-n }`
  - `next` picks first `--ready` card with no open run (list order: project list, then urgent DESC / position ASC). None → `NotFound { entity: "task", id: "ready" }`
  - `move_to_in_progress` calls `task_move_inner(..., Column::InProgress, None, now)` in the same transaction after insert
  - HTTP `app_error` maps `Conflict` with the other 409 variants

```rust
async fn next_inner(
    store: &mut dyn Store,
    actor: &Actor,
    cmd: NextClaim,
    now: DateTime<Utc>,
) -> Result<Run, AppError> {
    let ready = task_query_inner(
        store,
        TaskListQuery {
            project: cmd.project,
            ready: true,
            ..TaskListQuery::default()
        },
        now,
    )
    .await?;
    let mut claimed = None;
    for task in ready {
        let runs = store.list_runs(task.id).await?;
        if !has_open_run(&runs) {
            claimed = Some(task);
            break;
        }
    }
    let task = claimed.ok_or_else(|| AppError::NotFound {
        entity: "task".into(),
        id: "ready".into(),
    })?;
    let run = run_start_inner(
        store,
        actor,
        RunStart {
            task_display_id: task.display_id.clone(),
            agent: cmd.agent,
            session_id: cmd.session_id,
        },
        now,
        true,
    )
    .await?;
    if cmd.move_to_in_progress {
        task_move_inner(store, actor, &task.display_id, Column::InProgress, None, now).await?;
    }
    Ok(run)
}
```
